1. Създаване на таблици (CREATE TABLE) – Въпроси 1 (вариант 1 и 2)

1.1. Основен синтаксис

CREATE TABLE име_на_таблица (
    колона1 ТИП_ДАННИ ОГРАНИЧЕНИЯ,
    колона2 ТИП_ДАННИ ОГРАНИЧЕНИЯ,
    ...
);

В контролната работа трябва да попълвате липсващи думи като CREATE, PRIMARY, NOT, UNIQUE, DEFAULT, true.

1.2. Първичен ключ (PRIMARY KEY) и AUTO_INCREMENT

  • Първичен ключ (PRIMARY KEY): Уникален идентификатор за всеки запис.
  • Не може да е NULL и трябва да е уникален.
  • Често е цяло число с автоматично нарастване:
id INT PRIMARY KEY AUTO_INCREMENT
Пример като във въпрос 1 (вариант 1): 
CREATE TABLE customers (
    id INT PRIMARY KEY AUTO_INCREMENT,
    first_name TEXT NOT NULL,
    last_name TEXT NOT NULL,
    email TEXT UNIQUE NOT NULL,
    city TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

Ключови думи за попълване: CREATE, PRIMARY, NOT, UNIQUE

Пример като във въпрос 1 (вариант 2): 
CREATE TABLE categories (
    id INT PRIMARY KEY AUTO_INCREMENT,
    category_name TEXT NOT NULL UNIQUE,
    description TEXT,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

Ключови думи за попълване: CREATE, PRIMARY, NOT, true

1.3. Важни типове данни и ограничения за контролната

Тип / Ограничение Описание Пример от задачите
INT Цели числа id INT PRIMARY KEY AUTO_INCREMENT

BOOLEAN Булева стойност (true/false) is_active BOOLEAN DEFAULT true

2. Извличане на данни (SELECT, FROM, WHERE, ORDER BY) – Въпроси 2, 3, 4

2.1. Основен синтаксис

SELECT колона1, колона2, ...
FROM име_на_таблица
[WHERE условие]
[ORDER BY колона [ASC|DESC]]
[LIMIT брой];

2.2. Филтриране с WHERE (въпрос 2 – град Пловдив/София)

За да извадим всички клиенти от даден град:

SELECT first_name, last_name, email
FROM customers
WHERE city = 'Пловдив'
ORDER BY last_name ASC;

Същият шаблон се използва и за град София във втория вариант.

Ключови думи за попълване: SELECT, FROM, 'Пловдив' / 'София', ASC

2.3. Условия с AND, BETWEEN и филтриране по диапазон (въпроси 3 и 4)

  • BETWEEN a AND b – стойността е между a и b (включително)
  • AND – и двете условия трябва да са верни
Пример като във въпрос 3 (вариант 1): 
SELECT product_name, price, stock_quantity
FROM products
WHERE stock_quantity > 0 AND price BETWEEN 100 AND 800
ORDER BY price ASC
LIMIT 8;

В задачата попълвате: FROM, WHERE, ORDER, LIMIT.

Пример като във въпрос 4 (вариант 1): 
SELECT product_name, price, stock_quantity
FROM products
WHERE stock_quantity BETWEEN 1 AND 10
ORDER BY stock_quantity DESC
LIMIT 5;

В задачата попълвате: FROM, WHERE, DESC, LIMIT.

Пример като във въпрос 3 (вариант 2): 
SELECT id, customer_id, total_amount
FROM orders
WHERE total_amount > 1000
ORDER BY total_amount DESC;

В задачата попълвате: FROM, WHERE, ORDER, DESC.

2.4. Псевдоними (ALIASES) с AS – въпрос 7 (вариант 2)

С AS можем да дадем друго име на колона в резултата.

SELECT product_name AS product,
       price AS price,
       stock_quantity AS stock
FROM products
WHERE price BETWEEN 50 AND 500;

В задачата попълвате: AS, AS, AS, FROM.

3. Групиране и агрегатни функции (GROUP BY) – Въпроси 5, 6, 7

3.1. Основни агрегатни функции

Функция Какво прави Пример от задачите
COUNT(колона) Брои записи COUNT(id) AS customer_count
SUM(колона) Сумира стойности SUM(total_amount) AS total_spent
AVG(колона) Средна стойност AVG(price) AS avg_price
MAX(колона) Най-голяма стойност MAX(price) AS max_price
MIN(колона) Най-малка стойност MIN(price) AS min_price

3.2. GROUP BY и ORDER BY – въпрос 5 (вариант 1) и въпрос 4 (вариант 2)

GROUP BY групира записи по колона (напр. по град или категория).

Пример като във въпрос 5 (вариант 1): 
SELECT city, COUNT(id) AS customer_count
FROM customers
WHERE city IS NOT NULL
GROUP BY city
ORDER BY customer_count DESC;

В задачата попълвате: FROM, WHERE, GROUP, ORDER.

Пример като във въпрос 4 (вариант 2): 
SELECT category_id, COUNT(id) AS product_count
FROM products
GROUP BY category_id
ORDER BY product_count DESC;

В задачата попълвате: FROM, GROUP, ORDER, BY.

3.3. SUM по статус и филтриране с WHERE – въпрос 5 (вариант 2)

SELECT status, SUM(total_amount) AS total_revenue
FROM orders
WHERE status IN ('completed', 'delivered')
GROUP BY status;

В задачата попълвате: SUM, FROM, WHERE, GROUP.

3.4. Групиране по клиент и поръчки с голяма стойност – въпрос 6 (вариант 1)

SELECT customer_id, SUM(total_amount) AS total_spent
FROM orders
WHERE status = 'completed' AND total_amount > 500
GROUP BY customer_id
ORDER BY total_spent DESC;

В задачата попълвате: FROM, WHERE, GROUP, DESC.

3.5. MAX и MIN по категории – въпроси 7 (вариант 1) и 6 (вариант 2)

Пример като във въпрос 7 (вариант 1): 
SELECT category_id,
       COUNT(id) AS product_count,
       AVG(price) AS avg_price,
       MAX(price) AS max_price
FROM products
GROUP BY category_id;

В задачата попълвате: AVG, MAX, FROM, GROUP.

Пример като във въпрос 6 (вариант 2): 
SELECT category_id,
       MAX(price) AS max_price,
       MIN(price) AS min_price
FROM products
GROUP BY category_id;

В задачата попълвате: MAX, MIN, FROM, GROUP.

4.1. Основен синтаксис

В задачата попълвате: Иван, Петров, ivan.petrov@example.com, Пловдив.

В задачата попълвате: Лаптоп, 1200.00, 5, 2.

5. Първични и външни ключове, връзки между таблици – Въпроси 9 (PK/FK схеми)

5.1. Първичен ключ (PK)

  • Уникално идентифицира всеки запис в таблицата.
  • Примери:
    • customers.id
    • orders.id
    • order_items.id
    • clients.client_id
    • invoices.invoice_id
    • invoice_items.item_id

5.2. Външен ключ (FK)

  • Показва връзка между две таблици.
  • Стойността му е id от друга таблица.
  • Примери:
    • orders.customer_id е FK към customers.id
    • order_items.order_id е FK към orders.id
    • invoices.client_id е FK към clients.client_id
    • invoice_items.invoice_id е FK към invoices.invoice_id

5.3. Връзки между таблици (1:N)

  • Един клиент може да има много поръчки:
    customers (1) → orders (N)
  • Една поръчка може да има много редове (артикули):
    orders (1) → order_items (N)
  • Същата логика важи за:
    clients → invoices → invoice_items

В задачите трябва да отбележите с химикал кое поле е PK, кое е FK и да нарисувате стрелки между таблиците.

💡 Съвети за контролната работа

  1. Прочетете внимателно всяка задача – разберете каква заявка трябва да се получи.
  2. Вижте примера тук – почти всяка задача има аналогичен пример в този документ.
  3. Попълвайте логично празните места – помислете каква е ролята на ключовата дума.
  4. Обърнете внимание на главни/малки букви – при ключовите думи обикновено се ползват главни, но SQL не е case-sensitive.
  5. Внимателно със скобите и кавичките – текст в '...', числа без кавички.
  6. Накрая прегледайте всички задачи – проверете дали заявките са валидни и завършват с ;.
